# 校园打印 1.3.0｜部署与维护说明

运行要求：Windows x64 已验证 Node 24.16.0、npm 11；声明范围为 Node >=24.16.0 且 <25、npm >=11。当前交付为本机软件，公网、真实手机、纸张和资金验收单独记录。

## 新安装与现有安装

发行目录为 `dist/CampusPrint-V1.3.0-*`，解压后执行 `npm ci --omit=dev`，保留原生可选依赖。首次空安装才复制 `.env.example`、初始化数据库和管理员；无默认密码，密码只通过交互或受控进程环境输入。发行包不含真实库、学生文件、收款/广告素材、口令、`.env`、测试身份或 `node_modules`。

默认监听 `127.0.0.1:4328`，学生 `/` 或 `/user/`，管理 `/admin/`。Windows 可使用 `scripts/desktop/open-campus-print.ps1 -View user -SkipBrowser` 启动，`-View stop -SkipBrowser` 受控停止。正式广告开关 `ADVERTISEMENTS_ENABLED=false`，学生账号默认关闭但原资料保留。计价版本仍为1.1.0。

现有1.2.0升级新增105，不改写001–104。先停止对应服务，用保存的匹配1.2.0工具和明确真实存储路径保护最新数据库、有效学生文件、经营素材和独立最新期限 authority。新版 start、db:init、backup:create 都可能迁移，不能用新版给未升级旧库补备份。不要把恢复源码的默认 var 当正式库。

本轮实际迁移、发行哈希与恢复点见 `handoffs/流程精简与界面收敛/C-迁移与回退记录.md` 和 `C-完成交接.md`，原A/B记录及旧发行物保留。普通部署者应先在隔离目录验证包安装、旧库升级、金额与期限，再开放正式服务。

## 私有路径与维护

默认 DATA_DIR=`var`，下设 db、student-files、payment-assets、advertisement-assets、processing、file-ledger、managed-backups。DB_PATH、STUDENT_FILES_DIR、PAYMENT_ASSETS_DIR、ADVERTISEMENT_ASSETS_DIR、PROCESSING_DIR、FILE_LEDGER_DIR、MANAGED_BACKUPS_DIR 可分别配置，所有根必须独立、互不嵌套、无链接，不在前端静态目录中。

一库一个实例，勿删除活进程锁。离线清理先停同库服务，再运行 `npm run files:cleanup`；`files:manifest` 导出期限清单，`files:reconcile` 协调可信最新期限。停服不会暂停文件到期计算，若跨过更早期限，要用仍与库匹配的旧版工具先清理/协调，不能重复制续期。

实际送达后连续604800秒到期，未下单上传24小时；启动先协调清理，运行中每五分钟内扫描。清理失败仍禁访问并重试，不能通过回退、重印、退款或找回延长期限。已下载到设备的副本由持有人清理。

## 备份与回退

已升级且停服的同版本库可运行 `npm run backup:create`，独立全新空私有目录使用 `npm run backup:authority -- <绝对路径>`。快照含数据库、有效 ready 文档、期限清单/台账、两类经营图片；广告文件验证引用、大小和SHA-256，开关关闭也仍保留和恢复图片。文档副本不晚于该快照七天上限及更早权威期限。

回退前保全升级后新增订单、资金、经营设置和最新期限。旧源码与快照只恢复到全新空私有根，恢复前协调最新 authority 并核对，禁止用旧库覆盖新交易。缺少可信最新期限时只恢复记录，学生文件保持不可读。隔离恢复通过不代表真实服务已经回退。

## 验证与外网

源码使用 `npm test` 执行完整API、双端/跨端浏览器与77操作契约；新增界面夹具用 `npm run test:ui:fixtures` 单独记录。所有验证设 `CP_VERIFICATION_DIR` 到本轮新目录，禁止覆盖旧通过或失败记录。

公网需另行提供服务器、域名、HTTPS证书和实际代理配置，使用生产模式和真实同源地址，检查安全Cookie、Origin/CSRF、上传限额与访问边界。仓库代理/systemd示例未代表真实公网执行。广告上传原单次EBUSY观察尚未定位，关闭功能不能写成已修复。
