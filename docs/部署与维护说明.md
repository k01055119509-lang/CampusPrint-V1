# 校园打印 1.4.0 部署与维护

运行要求为 Windows x64、Node >=24.16.0 且 <25、npm >=11。本轮运行时为 Node 24.16.0 / npm 11.13.0。产品、包和契约为 1.4.0，计价版本仍为 1.1.0。默认学生账号关闭、广告关闭、首页公告未发布。

## 新安装

将干净发行 ZIP 解压到全新目录，使用 `npm ci --omit=dev` 安装锁定依赖。首次配置时才复制 `.env.example` 到 `.env`，核对全部存储根、监听地址和权限，再运行 `npm run db:init`、`npm run admin:init`。管理员初始化交互输入用户名和隐藏密码，无默认口令。运行 `npm start` 或 Windows 桌面启动脚本。

新包不含业务数据库、真实账号、学生文件、收款图、广告图、`.env`、测试证据或 node_modules。收款图未配置时仍可下单，不能提交付款声明。公网须另设服务器、域名、HTTPS 和访问防护；本机运行不表示公网已部署。

## 从 1.3.0 升级

1. 先核对实际版本、进程、监听和所有正式存储路径，保全最新已提交订单、资金记录、账号、经营图片及独立最新 authority。不要使用规划快照或旧订单计数替代当前备份。
2. 用与当前九迁移库匹配的 1.3.0 工具完成恢复保护并受控停止对应服务，确认处理结束、锁和实例释放。停服不暂停文件及备份副本期限。
3. 先在唯一隔离根验证同一 ZIP 的锁文件安装、原生依赖、空库启动、九迁移旧库升级、业务与素材备份恢复以及桌面启停。
4. 最后核对冻结源码和已测 ZIP 一致，再对正式库受控应用新增 `106-cancellation-notice.sql`，总迁移数为十；001–105 不修改。保留历史取消来源、已记录收款、原金额及文件期限。既有账号和图片无需重新初始化或导入。
5. 检查公开配置、三个页面入口、管理员权限、双渠道图片、广告关闭、公告未发布，以及旧列、账号、金额和台账摘要。不要在正式库造订单、发券或模拟收退款来验收。

本轮是否已经在本机升级及其实际服务状态，请看 `docs/handoffs/公告与取消补偿改版/C-迁移与回退记录.md` 和本轮独立验证记录；本说明描述步骤，不替代执行证据。

## 清理、备份和回退

实际送达起连续七天后禁访问并清理学生文件；未下单上传另按 24 小时处理。备份中的学生副本不晚于该快照创建起七天或更早权威期限，备份、恢复、停服、取消、退款及补偿均不续期。正常运行会启动扫描并每五分钟内周期清理；停服期间必须由接手者按匹配版本工具和显式全部存储根维护。

源码维护入口：`npm run files:cleanup`、`npm run files:manifest`、`npm run backup:create`、`npm run backup:authority -- <全新私有目录>`。离线维护应先受控停止同库服务。正式库升级后不能再使用 1.3.0 工具连接它。

回退前先用已升级版本保存新增交易、最新经营图片和 authority，再在全新、空、无链接的私有目标恢复旧源码及合法快照，并协调最新期限。没有最新 authority 时仅恢复记录，学生文件保持不可读。禁止用旧库直接覆盖升级后新事实。演练结果和实际正式回退分别记录。

## 验证和发行

源码目录的 `npm test` 依次实际运行完整 API、真实浏览器和契约校验；`npm run test:ui:fixtures` 为独立界面夹具。使用 `CP_VERIFICATION_DIR` 指向本轮唯一证据根，默认目录为 `docs/verification/cancellation-notice-v1.4.0/C/`。同包安装验证使用 `scripts/deploy/verify-cancellation-release.js`，升级前门槛为 `scripts/deploy/check-cancellation-upgrade.js`。

本轮已有广告上传 EBUSY 历史观察，根因未定位；若再现，保留脱敏操作及文件错误步骤交后端责任方。不能用隐藏广告、吞掉错误或删除素材恢复回归代替处理。软件验收、实际资金、纸张试印、实体配送、真实手机和公网验收分别报告。
