## 3. D 完成的修复和补齐

1. 原根 npm test 只执行 A，产品版本仍为 A 阶段。统一 1.0.0 和全项目测试入口，旧基础页面检查别名转到现行完整界面；聚合契约保留 A/B稳定接口。
2. 原文件引擎具备台账/manifest/reconcile，但缺少实际部署备份包装。新增短事务外 SQLite 一致备份、逐文件快照、原时间/更早订单期限清理、启动/周期自动扫描、失败后台提示与恢复前离线核验。没有长期包含全部学生文档的 ZIP。
3. Windows 直接结束子进程不会可靠执行 Unix 信号关闭流程。加入显式本地 stdin stop 管道，实测退出码0和数据库锁释放；前台 Ctrl+C 继续可用，不增加 HTTP 停服接口。
4. A 契约生成器会覆盖 B 聚合路径。改为保留已存在聚合业务路径及版本，同步新增备份清理状态结构；实际48路由契约已通过。
5. 发行采用白名单，去除仅开发使用的测试入口和devDependencies，保留实际运行维护命令及许可；正式配置仍为空收款、无测试数据。
6. 恢复中途失败留下pending标记，普通启动拒绝开放HTTP；合成文档校验失败及随后启动拒绝已验证，避免部分恢复结果未经核验被使用。

没有改价、改变七天起算、引入付款平台、复制旧库或扩展配送楼栋。原计价与订单状态核心经过独立回归，未发现需改写的业务规则缺陷。
